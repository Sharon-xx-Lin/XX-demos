# 兴趣内容驱动的英语复述学习 App 功能描述文档

> **文档用途**：本文档用于交付给 AI 进行开发，描述「做什么」与「为什么」，不含技术选型与架构设计。
> **状态**：全部需求决策已由产品确认，可作为开发依据。决策记录见 §8。
> **标记说明**：`✅ 已确认` = 产品已拍板；`⚙️ 首期默认` = 澄清阶段未做明确决策、由需求方给出的合理默认值，开发前如无异议即按此执行。

---

## 1. 背景与目标

### 需求来源

自主发起的 0-1 新产品。源于一个观察：成年人的英语学习失败，绝大多数不是因为方法不对，而是因为**读不下去**——教材枯燥，学习被设计成一件需要意志力对抗的事。

### 产品理念（贯穿所有功能设计的准则）

本节不是背景说明，而是**功能设计的判定依据**。当某个功能设计存在多个选项时，以是否符合本节理念作为取舍标准。

| 理念 | 对功能设计的约束 |
|------|-----------------|
| **帮助人们坚持做难以坚持但世俗意义上有用的事** | 产品的第一目标是「让用户下次还会打开」，而非「让用户单次学得更多」 |
| **Content is king。学习 = 内容消费** | 内容质量与兴趣匹配度优先于练习形式的丰富度；不自制教材，而是帮用户找到真正想看的内容 |
| **不要 PUA 自己。只要学习了，就是胜利** | 禁止任何形式的惩罚性反馈、归零惩罚、羞耻感设计；完成即胜利，不做质量门槛 |
| **「可持续」比「效率」重要** | 拒绝任何以提升单次学习效率为名、但会增加用户心理负担的设计 |
| **把「内耗」变成「外耗」** | 学不下去时，产品应主动归因于「素材不够吸引人」并帮用户换内容，而非提示用户「再坚持一下」 |

### 业务目标

1. **建立复述学习闭环**：让用户完成「消费真实英文内容 → 向 AI 语音复述 → 获得专业且鼓励的反馈」这一完整闭环，形成有输出的学习行为。
2. **降低开口门槛**：把「向 AI 说英语」的心理门槛降到足够低，使胆怯的用户也能完成第一次复述。
3. **形成可持续的学习习惯**：通过内容吸引力（而非意志力施压）驱动用户持续回访。

### 成功指标

| 指标 | 定义 | 说明 |
|------|------|------|
| **首次复述完成率** | 新用户注册后完成首次完整闭环（消费素材 + 复述）的比例 | **最关键的前置指标**。复述环节是最大流失点 |
| 次日 / 7 日 / 30 日留存 | 标准留存 | 检验「内容驱动」是否真的比「意志力驱动」更可持续 |
| 人均周打卡次数 | 每周完成完整闭环的次数 | 衡量习惯强度，注意不要异化为对用户的施压指标 |
| 素材完成率 | 进入素材消费页后完成消费的比例 | 反映素材推荐的切题度与难度匹配度 |
| 短素材使用占比 | 3 分钟以内素材的消费占比 | 验证「防畏难」设计是否被真实使用 |

⚙️ **首期默认**：暂不设定量化目标值。首个版本以「跑通闭环 + 拿到真实基线数据」为目标，上线运行 1 个月后再基于真实数据设定目标值。理由：0-1 新产品无历史基线，此时设定的目标值缺乏依据，且容易在早期就把团队注意力从「产品是否成立」转移到「数字是否达标」。

## 2. 用户与场景

### 目标用户

✅ **已确认**

- **核心画像**：**18–45 岁**、中文母语、CEFR **A2–B2** 水平的成年英语自学者。
- **典型特征**：
  - 不缺学习资源，缺的是「能看得下去的资源」和「说出口的机会」
  - 有内容消费习惯（刷视频、听播客、追兴趣圈层），但消费后无语言沉淀
  - 有过多次「下载学习 App → 用几天 → 弃用」的经历
  - 对「学习成果被量化考核」敏感，容易因断签产生挫败感
- **最大能力约束**：**多数人不敢开口**。这是产品最大的转化瓶颈——用户可能愿意看素材，但会在「向 AI 语音复述」这一步流失。所有相关功能设计都必须为此让路。
- **年龄跨度带来的设计影响**：18–45 岁跨越两代人，衍生出主题选品、UI 无障碍、视觉语言、场景权重四类要求。**完整定义见 §4.8 交互设计原则**（该节为唯一真值来源，避免多处并行维护）。

### 核心场景

| 场景 | 触发情境 | 用户状态 | 对产品的要求 |
|------|---------|---------|-------------|
| **碎片时间练一次** | 通勤、午休、睡前 | 只有 5–10 分钟；环境可能不便出声；网络可能不稳定 | 必须有 3 分钟内的短素材；需要不便出声时的兜底路径。⚠️ 注意：音视频**不能**离线缓存（§7.1 政策约束），弱网场景只能靠文本素材承接 |
| **兴趣驱动的深度消费** | 周末、对某主题正有热情 | 愿意投入 20–30 分钟 | 需要长素材 + 更充分的多轮对话 |
| **维持记录不想断** | 接近当日结束 | 疲劳，只想低成本完成 | 必须存在「最低成本达成打卡」的合法路径，且不让用户为此感到羞耻 |

## 3. 功能需求

### 3.1 主题输入与素材检索

**功能描述**
用户输入或选择一个感兴趣的主题（如 AI 资讯、KPOP、民族文化），系统返回该主题下经筛选的英文学习素材列表，长短混排。

**业务规则**

**① 主题体系** ✅ 已确认

- 系统**首期上线固定 16 个预置主题**（下列为必含项，非举例），以卡片形式展示：

  | # | 主题 | 偏向人群 |
  |---|------|---------|
  | 1 | AI 与科技 | 通用 |
  | 2 | KPOP | 偏年轻 |
  | 3 | 影视剧集 | 通用 |
  | 4 | 商业财经 | 偏 30 岁以上 |
  | 5 | 旅行 | 通用 |
  | 6 | 体育 | 通用 |
  | 7 | 民族与人文 | 偏 30 岁以上 |
  | 8 | 科普 | 通用 |
  | 9 | 时事新闻 | 偏 30 岁以上 |
  | 10 | 游戏 | 偏年轻 |
  | 11 | 美食 | 通用 |
  | 12 | 职场与沟通 | 偏 30 岁以上 |
  | 13 | 心理与自我成长 | 通用 |
  | 14 | 音乐 | 偏年轻 |
  | 15 | 健康与运动 | 偏 30 岁以上 |
  | 16 | 环境与可持续 | 通用 |

- **主题上线门槛（入库 SLA）**：主题只有在满足「库内 ≥30 条素材，其中 ≥2 条 3 分钟以内短素材」时才允许出现在预置列表中。不满足门槛的主题**不上线**，而非上线后再补
- 同时提供**自由输入框**，用户可输入任意主题
- 输入命中预置主题或其语义近义时，返回对应素材（匹配规则见下方 ⑥）
- **输入未命中时，如实告知「暂无该主题素材」，并提供「订阅该主题」按钮**——不做静默降级到不相关主题（违背「素材一定要切题」的要求）
- **订阅闭环**：订阅记录既是素材库扩充的需求信号，也是**通知触发源**。当被订阅主题首次满足上线门槛时，向所有订阅者推送一次通知（「你订阅的『滑雪』主题已经有素材了」）。订阅列表在「我的」页可见可取消

**② 检索实现形态**（受硬约束限定，无替代方案）

- 面向用户的产品语言是「AI 为你检索素材」
- 实际实现必须是「**预建的主题化素材库 + 语义匹配**」，**不得**在用户每次输入时触发对第三方平台的实时搜索
- 原因：YouTube Data API 默认配额为每项目每天 10,000 units，单次 `search.list` 消耗 100 units，即全平台每天仅支持约 100 次搜索，且无法付费购买配额。详见 §7.2
- 素材库的建设与更新走后台运营流程，该后台是**首期必需交付物**，需求见 §3.11

**③ 素材列表构成规则**

- 每次返回的素材列表**必须至少包含 1 条 3 分钟以内的短素材**，且在列表中**显著置顶或高亮标记**（如「3 分钟速通」标签）
- 这是产品级硬规则，不是运营建议。目的是防止用户因畏难而流失
- 列表内素材应长短混排，覆盖短（<3 分钟）/ 中（3–10 分钟）/ 长（>10 分钟）三档时长
- **短素材耗尽时的处理**（避免与「禁止静默降级」冲突）：
  - 首选由 ① 的上线门槛保证不发生（主题上线即有 ≥2 条短素材）
  - 若运行期该主题短素材已全部被用户消费过，**允许从相近主题补位，但必须显式标注来源**：「这条来自『科普』主题，同样简短易上手」
  - **禁止静默替换**——标注后的跨主题补位不属于静默降级，用户知情即可
  - 运营后台需对「短素材库存 < 2 条」的主题触发告警（见 §3.11）

**④ 素材筛选规则（入库审核标准）**

| 维度 | 规则 |
|------|------|
| 切题度 | 内容主体必须与主题直接相关，不接受仅标题沾边 |
| 公开性 | 必须为公开可访问内容，不得需要登录 / 付费 / 会员才能观看 |
| 口音 | 不接受口音过重的视频与播客；优先英美加澳主流口音 |
| 字幕语言 | **不允许存在英文以外语言的字幕轨** |
| 时长 | 需标注准确时长，用于列表分档 |
| 内容安全 | 不含政治敏感、色情、暴力、歧视内容 |
| Made For Kids | 需查询并记录每个 YouTube 视频的 Made For Kids 状态，对该类视频关闭追踪（政策要求） |

> ⚠️ **字幕语言的判定方式限制**：只能通过 API 返回的字幕轨**语言列表元数据**判断，**不得**下载字幕正文进行检查（`captions.download` 需视频所有者授权，第三方无权调用）。详见 §7.2。

**⑤ 难度分级规则**

- 难度只做**粗粒度三档：易 / 中 / 难**，**不做 CEFR 六级细分**
- 原因：CEFR 六级自动化分级准确率仅约 62.6%，三大级约 82.6%。分级标错（尤其把难素材标成「易上手」）会直接摧毁用户信任并放大畏难流失。详见 §7.3
- 音视频素材额外标注**语速档位（慢 / 中 / 快）**作为独立难度因子——语速快的简单词汇内容对听力仍然是难的
- 素材卡片上同时展示：时长 + 难度档 + 语速档（音视频）
- 标注方式：**自动预标 + 人工复核**（见 §3.11）

**⑥ 主题输入的匹配与异常分支**

| 输入情形 | 处理方式 |
|---------|---------|
| 命中预置主题名 | 直接返回该主题素材 |
| 命中别名 / 近义词 / 常见错拼 | 直接返回，无需二次确认。需维护**主题别名表**（含中英双语、常见错拼，如 "K-pop" / "kpop" / "韩流"） |
| 语义高相似（超过命中阈值） | 直接返回，并轻提示「为你匹配到『XX』主题」 |
| 语义中等相似（疑似命中） | **二次确认**：「你是想看『商业财经』相关的内容吗？」，用户确认后返回 |
| 语义低相似（未命中） | 告知暂无该主题素材 + 提供订阅按钮 |
| 多主题混合输入（如「KPOP 和职场」） | 提示择一：「想先看哪个？」并列出识别到的主题，不做交集检索 |
| 无意义输入（如 asdfgh、纯符号） | 独立提示「没太看懂，试试输入一个你感兴趣的话题？」+ 展示预置主题卡片，**不进入订阅流程** |
| 命中敏感词 | 独立提示「换个话题试试吧」，**不进入订阅流程**、不记录为需求信号 |
| 输入超长 | 输入框限制 30 字符 |

- 具体的相似度阈值由实现阶段调优，但**必须存在「疑似命中 → 二次确认」这一档**，不允许只有命中/未命中两态（否则边界体验极差）
- 同一用户的主题输入频次上限：60 次/小时（防滥用）

**输入 / 输出**

- 输入：主题文本 或 主题卡片选择
- 输出：素材列表。**每条素材卡片的字段为本文档唯一真值，§4 各页面卡片必须与此一致**：

  | 字段 | 说明 | 缺失时降级 |
  |------|------|-----------|
  | 标题 | 素材原标题 | 必有 |
  | 一句话内容摘要 | **中文**，降低点击决策成本；由 AI 生成 + 人工抽检 | 隐藏该行 |
  | 封面图 | 视频/播客取来源封面；文本取默认主题配图 | 显示主题色占位块 |
  | 类型图标 | 文本 / 视频 / 音频 | 必有 |
  | 时长 | 分钟数 | 必有 |
  | 难度档 | 易 / 中 / 难 | 必有 |
  | 语速档 | 慢 / 中 / 快（仅音视频） | 文本素材不显示 |
  | 来源平台 | 归属标识（政策要求，见 §7.1） | 必有 |

### 3.1.1 今日推荐

**功能描述**
主页的默认素材供给。用户无需先选主题即可直接开始学习——这是「最低成本达成打卡」场景的关键路径。

**业务规则**

1. **推荐数量**：每日 **3–5 条**，其中**必含至少 1 条 3 分钟以内短素材**并置顶标记
2. **排序依据**（优先级从高到低）：
   - 用户已订阅的主题
   - 用户历史消费过的主题（近 30 天权重更高）
   - 与用户水平档匹配的难度（水平来源见 §3.9①）
   - **未被该用户消费过**（去重规则见下）
3. **去重规则**：已完成消费的素材不再进入今日推荐；**未完成消费**的素材可再次出现，并标记「上次看到 X 分钟」
4. **刷新时机**：每个「学习日」起点（见 §3.5 日界定义）刷新一次。当日已消费的素材保留在列表中并标记为已完成，不立即移除（让用户看到当天的进展）
5. **冷启动**（新用户未选任何主题、无消费历史）：推送**通用高质量短素材**——从各主题中选取难度「易」、时长 <5 分钟、且历史完成率最高的素材
6. **「换一批」行为**：同主题池内换一批，每日可换 3 次；换出的素材不计入去重（下次仍可能出现）
7. **一键直达**：今日推荐**首卡支持从主页一键进入消费页**，无需先选主题——这是 §4.8「核心路径决策数」指标的关键设计
8. **首次进入的特殊呈现**（✅ 已确认，直接服务于「首次复述完成率」这一第一指标）：
   - 标题为**「从这条开始」**，**只指定一条素材**而非给出列表 —— 选择本身是新用户流失的首要原因
   - 该条必定满足：**时长 ≤3 分钟、难度「易」、语速「慢」**
   - 副标题明示成本与门槛：**「两分半，说一句就算完成」** —— 同时打掉时间成本与输出压力两种畏难
   - 其余素材以「也可以看这些」轻量带出，保留选择权但不构成决策压力
   - ⚠️ **首次进入时不显示打卡数据区块**（不显示「0 天 / 0 次」）—— 零值对新用户是负向信息，与「不要 PUA 自己」冲突。完成首次打卡后该区块才出现

### 3.2 素材消费

**功能描述**
承载素材本体的阅读 / 观看 / 收听，并在消费完成后引导进入复述环节。

**业务规则**

**① 素材类型范围** ✅ 已确认：三类全做

- **文本素材**：文章、资讯、博客等
- **视频素材**：通过官方嵌入播放器播放
- **播客 / 音频素材**：通过原始 CDN 流式播放

**② 播放与呈现规则**（受硬约束限定）

- 视频必须通过**官方嵌入播放器**（YouTube IFrame Player API）播放，**不得**下载、转存、缓存音视频、提供离线播放
- **不得**遮挡或改造播放器控件、**不得**屏蔽或替换播放器内广告、**不得**移除来源平台的归属标识与播放器内链接
- 播客音频必须由其原始 CDN 直接流式分发，不得缓存或预加载
- 页面 UI 设计只能在播放器**之外**的区域做延展
- 提供「在原平台打开」的深链跳转入口
- 详见 §7.1

**③ 消费辅助能力**

- 文本素材：原文阅读器，支持字号调节
- 视频 / 音频：支持倍速播放（0.75x / 1x / 1.25x / 1.5x）；字幕或文稿对照展示（若来源提供）
- 生词点查：✅ 已确认**首期不做**，避免分散核心闭环的精力

**④ 完成判定与消费进度**

- 用户可主动点击**「进入口语复述」**进入复述环节（该文案为定稿，全程统一，不做首次特殊文案）
- 系统记录实际消费进度（阅读滚动进度 / 播放进度），用途有二：① 素材完成率统计；② **决定复述评价的范围**（见 §3.3④）
- **不以进度达标作为进入复述的前置条件**——用户随时可以进入复述（符合「不设门槛」理念）
- 消费进度 <70% 时点击进入复述，给出**温和提示但不阻断**：「还没看完，要不要先看完？效果会更好」，提供「继续看」与「就现在复述」两个选项；**两个选项视觉权重相同、默认不预选任何一个**（若把「继续看」做成主按钮，本质是在施压）
- **未完成消费的素材**记录断点位置，下次可从断点继续（今日推荐中标记「上次看到 X 分钟」）

**页面状态**

- 加载中
- 素材加载失败 / 素材已在原平台下架 → 提示并推荐替代素材
- 字幕不可用 → 明确告知，不阻断消费

### 3.3 AI 语音复述与反馈（核心功能）

**功能描述**
用户用英文**语音**向 AI 复述刚消费的素材内容，AI 以**语音实时对话**的方式回应、追问与引导，形成一段真实的口语交流。会话结束后自动转写为文字稿与学习报告。

这是产品的核心差异化功能，也是最大的流失点。所有设计以「让用户敢说出第一句」为最高优先级。

**业务规则**

**① 交互形态：真实语音对话**（✅ 已确认，非文字聊天）

这是产品的立身之本，不可降级为文字问答形态。

| 要求 | 说明 |
|------|------|
| **双向语音** | 用户说英文，**AI 也用语音回应**。不是「用户说话 → AI 输出文字」的半程形态 |
| **实时性** | AI 响应延迟需控制在自然对话可接受范围内，允许边听边处理 |
| **可打断** | 用户可在 AI 说话时打断，如同真实对话 |
| **文字稿同步** | 对话过程中同步生成文字转写，供用户回看当下说过的内容（**辅助，不是主界面**） |
| **文字复述为兜底** | 仅在不便出声或麦克风不可用时启用（见 ⑥），**不是并列的主要形态** |

> ⚠️ **禁止的形态**：把复述做成「用户打字 → AI 回文字」的聊天窗口。产品的价值在于「敢开口说」，打字形态从根本上绕过了这个价值。

**② 双模式复述**（防畏难的关键设计）

| 模式 | 适用用户 | AI 行为 |
|------|---------|---------|
| **引导模式**（新用户默认） | 首次使用、水平较低、胆怯的用户 | AI 用语音主动把复述拆成小步：先问「这个内容主要讲了什么？一句话就好」，再逐步追问细节；用户卡住时主动给出句子开头的语音提示；允许用简单句 |
| **自由模式** | 有信心的用户 | AI 只给一个开放式起点（「跟我说说你看到了什么」），由用户自主组织完整复述 |

- 用户可在会话中随时切换模式
- 首次使用默认进入引导模式；系统可根据历史表现推荐模式，但**不强制**

**③ 会话结构与终止机制**（必须有，否则打卡无从判定）

- 会话遵循固定骨架：**开场 → 首个问题 → 多轮往返 → 收尾**
- 达到设定轮次后，AI 主动引导收尾并给出总结，**不允许会话无限延长**
- 用户可在任意时刻主动结束会话
- ✅ 已确认：默认往返轮次上限 **4–6 轮**，引导模式可略多（因引导模式会把复述拆成小步，需要更多轮次才能覆盖完整内容）

**④ 反馈的两段式结构**（⚠️ 对话中与报告中的反馈形态**不同**，这是语音形态的必然结果）

语音对话里逐句纠错会打断交流节奏，且英文语法解释用听的方式**记不住**。因此反馈分两段：

| 阶段 | 形态 | 内容 |
|------|------|------|
| **对话进行中** | 语音、隐性 | 采用二语习得中的 **recast（重铸）**：AI 不打断、不逐句纠错，而是在自然回应里把正确说法带出来。例：用户说 "It talk about chips"，AI 回应 "Right, **it talks about** why chips are hard to make. What part surprised you?" —— 正确形式在自然对话中被示范，用户无感知地接收 |
| **会话结束后** | 文字、显性 | 在学习报告中汇总，可反复回看（见 §3.4） |

**对话中的硬性约束**：

- ❌ **禁止**在对话中打断用户纠正语法
- ❌ **禁止**在对话中念出语法术语（如「主谓一致」「动名词」）
- ✅ AI 的每次回应必须**先承接内容、再自然重铸**，重心在推进对话而非纠错
- ✅ 只有当错误**导致理解失败**时，AI 才可显式确认：「你是说……吗？」

**⑤ 纠错的取舍原则**（✅ 已确认：实用导向，非应试导向）

> **核心原则：不影响理解与自然度的错误，不纠。**

产品目标是**能用英语交流**，不是通过考试。因此纠错必须做严格取舍：

| 处理方式 | 错误类型 | 举例 |
|---------|---------|------|
| **必纠**（影响听懂） | 用词错误导致意思偏差、句子结构混乱到听不懂、关键信息表达错误 | 把 "expensive" 说成 "cheap"；语序混乱到无法解析 |
| **必纠**（表达不地道到显眼） | 中式英语直译、明显不会有母语者这样说 | "I very like it" → "I really like it" |
| **可纠**（有余量时才提） | 更自然的高频表达替换 | "very difficult" → "tough" / "tricky" |
| **不纠** | 不影响理解的语法细节：三单 -s、冠词、可数不可数、时态小偏差、介词细微误用 | "It talk about…"、"the chip is expensive" 少冠词 |

- **每次会话的显性纠错上限：2 条**（原为 3 条，因实用导向下真正值得纠的更少）
- 纠错必须给出**可直接复用的整句表达**，而非语法规则说明
- 报告中的纠错项**不使用语法术语命名**，改用「更自然的说法」这类实用表述
- ⚠️ **禁止**呈现语法知识点清单、错误类型统计、语法正确率等应试化内容

**⑥ 评价维度**（⚠️ 已按实用导向重构，不再沿用 IELTS 应试框架）

原方案借用 IELTS 四维，但 IELTS 是考试评分框架，直接沿用会使反馈滑向应试化。改为**以「能否有效沟通」为核心**的四维：

| 维度 | 关注什么 | 明确不关注 |
|------|---------|-----------|
| **内容传达** | 有没有把关键信息说清楚？听者能否理解你的意思？ | 是否覆盖了素材的全部要点 |
| **表达自然度** | 说法是否地道？有没有中式英语痕迹？ | 词汇量大小、是否使用高级词汇 |
| **交流流畅度** | 能否持续把话说下去？卡顿是否影响沟通？ | 语速快慢、停顿次数统计 |
| **可听懂度** | 发音是否让对方听得懂？ | 口音是否接近母语者、音素级准确度 |

- ✅ 已确认：**首期不向用户展示分维度评分**，四维仅作为 AI 生成反馈时的内部框架，并沉淀到用户画像
- **评价范围随消费进度收缩**（与 §3.2④「无进度门槛」配套的必要规则）：
  - AI 只针对用户**已消费的部分**评价内容传达，并在开场说明范围：「我们就聊你看到的这部分」
  - 消费进度 <30% 的会话，**不将「内容传达」维度计入用户画像**（其他三维正常计入）
  - 任何情况下都**不因消费不完整而扣分或提示遗憾**

**⑦ 反馈语言规则** ✅ 已确认：**语音全英文，语言环境优先**

> **核心原则：AI 说出口的每一句话都是英文。**语言环境是产品价值的一部分 —— 一旦 AI 开口说中文，沉浸感即被破坏，用户也会失去"必须用英语应对"的压力与练习机会。

**① 语音内容（AI 说出来的）—— 全部英文，无例外**

| 语音成分 | 语言 | 说明 |
|---------|------|------|
| 开场、提问、追问 | **英文** | — |
| 自然回应与重铸（recast） | **英文** | 见 §3.3④ |
| 卡住时的句子开头提示 | **英文** | — |
| 鼓励与收尾 | **英文** | — |
| 理解确认（「你是说……吗？」） | **英文** | "Do you mean...?" |

**分级方式是调节英文难度，而不是切换到中文**：

| 用户水平 | 英文难度 |
|---------|---------|
| A2 | 短句、高频词、语速偏慢、必要时重复关键词 |
| B1 | 日常自然表达、正常语速 |
| B2 | 完整自然语速、可用地道表达与习语 |

- ❌ **禁止** AI 语音中出现任何中文，包括「中文括注」「中文补充说明」
- ❌ **禁止**中英夹杂在同一句内（如 "你的 pronunciation 很好"）
- ✅ 用户听不懂时的正确处理：**用更简单的英文重说一遍**（rephrase），而非切换成中文
- ✅ 若用户明确请求（说 "in Chinese" 或点击「看中文」），可提供**文字**中文翻译，但 **AI 语音仍保持英文**

**② 界面文字的语言分层**（⚠️ 与 ① 配套，否则沉浸感仍会失效）

| 文字类型 | 语言 | 默认状态 |
|---------|------|---------|
| 对话文字稿中 AI 的话 | 英文 | 显示 |
| 对话文字稿中的中文翻译 | 中文 | **默认隐藏，点击「看中文」才展开** |
| 学习报告中的「更自然的说法」对照 | 英文 | 显示 |
| 学习报告中的书面解释（为什么这样说更自然） | **中文** | 显示 |
| 系统提示、按钮、设置项、错误提示 | 中文 | 显示 |

> ⚠️ **为什么中文翻译必须默认隐藏**：如果翻译与英文并排常显，用户会直接读中文、跳过听英文，语言环境等于没有建立。改为「按需点开」后，用户先尝试听懂，实在不行才看 —— 这才是有效的沉浸设计。
>
> ⚠️ **为什么报告里的书面解释保留中文**：报告是**会话结束后**的复盘场景，此时已脱离语言环境，首要目标变为「让用户真正理解为什么」。对 A2 用户而言，英文语法解释会导致反馈完全失效。这与 ① 不冲突 —— ① 约束的是 AI 的语音，此处是书面复盘。

**③ 用户设置**

- 「我的」页提供**「报告解释语言：中文 / 英文」**开关（仅影响报告中的书面解释，B2 用户可切英文）
- **不提供「AI 语音语言」开关** —— 语音永远英文，这是产品的核心设定，不可配置

**⑧ 不便出声场景的兜底** ✅ 已确认：提供，但**仅作兜底，不是并列的主要形态**

- 触发条件：麦克风不可用 / 未授权，或用户在不便出声的环境主动切换
- 提供「改用文字复述」入口，用户可打字完成复述
- AI 对文字复述给出同样的反馈（不含「可听懂度」维度）
- **文字复述与语音复述在打卡判定上完全等价**（符合「学了就比不学强」理念）
- ⚠️ 但界面上**语音必须是默认且视觉主导的入口**，文字入口为次级（Web 端例外，见 §3.8①）。理由见 ①：打字形态绕过了产品的核心价值

**⑦ 跨会话记忆与个性化**

- 会话结束后，系统从对话记录中抽取用户信息（兴趣主题、常见错误类型、水平变化），沉淀为用户画像
- 后续会话注入该画像，使 AI 能延续上下文（如「上次你提到喜欢 KPOP，这次这条内容你觉得怎么样？」）
- 常见错误累积用于生成个性化的针对性练习建议
- ✅ 已确认：**个性化练习放二期**。首期只做画像沉淀（错误累积、兴趣记录）与跨会话记忆，不做基于错误生成的专项练习——需要足够的历史数据积累后才有效

**⑩ 反馈质量的保障机制**（把风格准则从「原则」变成可强制、可测的规格）

§3.3④⑤ 的要求若只作为提示词里的自然语言约束，无法保证每次输出都合规。必须配套以下三层机制：

1. **结构化输出**（用于生成学习报告，非对话中呈现）：AI 必须返回结构化字段，由客户端渲染：

   | 字段 | 约束 |
   |------|------|
   | `did_well[]` | 做得好的具体点，必填，不允许为空或空泛套话 |
   | `corrections[]` | **数组长度上限 2**（超出则截断），每项含 `heard`（用户原话）/ `natural`（自然说法）/ `why`（中文说明，**不得含语法术语**）|
   | `useful_phrases[]` | 本次可直接复用的整句表达 |
   | `encouragement` | 鼓励收尾，必填 |

   这样「纠错 ≤2 条」成为**程序可强制的约束**，而非依赖模型自觉。

2. **双重禁用词表校验**：
   - **风格禁用词**：① 打分与评级类（不及格、差、错误率）；② 比较类（比别人、大多数用户）；③ 努力程度类（不够努力、要更认真）
   - **应试化禁用词**（新增，对应 ⑤ 的实用导向）：语法术语类（主谓一致、动名词、时态、冠词、可数名词、定语从句…）、评分类（语法正确率、错误统计）
   - 输出命中则重新生成，重试 2 次后仍命中则降级为仅输出 `did_well` + `encouragement`
3. **固定评测集**：建立 20–30 条回归用例作为基线，必须覆盖：超短复述（仅一句）、全程说中文、完全跑题、**只有轻微语法错误但表达清楚**（预期：不纠错）、**中式英语但语法正确**（预期：必纠）、复述内容与素材矛盾、消费进度极低。每次提示词或模型变更后跑一遍。

**⑪ 录音数据处理规则**

| 项 | 规则 |
|---|------|
| 原始音频留存 | 转写完成后**服务端默认不留存原始音频**。如需短期留存用于识别纠错，最长 7 天且必须提供关闭开关 |
| 模型训练 | **默认不用于模型训练**。如需使用必须通过独立的授权开关，不得包含在通用用户协议中默认勾选 |
| 「删除录音」语义 | 仅删除音频文件，**不影响**转写文本、AI 反馈、学习报告 |
| 「删除学习记录」语义 | 另设独立入口，删除该次会话的全部内容（含报告）。**删除后打卡天数不回退**（符合「只增不减」原则） |
| 跨端同步 | 录音**不参与**跨端同步（仅转写文本同步），避免流量与存储成本 |

**页面状态与异常分支**

| 状态 | 处理方式 |
|------|---------|
| 麦克风权限未授权 | 引导授权，并同时提供文字复述入口（不强制授权） |
| 语音识别失败 / 结果明显错误 | 允许重说，或转为文字输入 |
| **AI 语音合成失败** | 降级为文字气泡呈现该轮回应，对话继续，不中断会话 |
| **用户打断 AI 说话** | AI 立即停止当前语音并转入聆听状态（真实对话的必要行为） |
| **环境噪音过大导致无法识别** | 提示「这里好像有点吵」并建议改用文字复述，不反复失败 |
| **用户长时间静默** | 引导模式下主动给出句子开头的语音提示；自由模式下等待更久后再介入 |
| AI 响应中 | 明确的等待反馈（语音形态下需有听觉或视觉的"正在思考"信号） |
| 网络中断 | 保留已有对话，支持恢复 |
| **AI 服务超时或报错** | 自动重试 2 次；仍失败则提示「教练这边有点卡，你说的已经保存了」。**该轮不消耗轮次**。已完成 ≥1 个有效轮次的会话**仍可结束并计打卡**，报告标记「部分反馈缺失」并提供重试生成入口 |
| **用户口述内容触发内容安全策略** | AI 温和转移话题：「我们把话题带回这条素材上吧」。**不指责、不中断会话、不影响打卡判定**（不得违反「禁止拒绝给出反馈」红线） |
| **用户全程说中文** | AI **用英文**鼓励并给出英文句式开头（"No worries — try it in English. Just one line: It's about..."）。**不计入改进点、不视为错误**。若用户连续 2 轮仍说中文，AI 用更简单的英文重说一遍（rephrase）并可建议换更简单的素材或改用文字复述 —— **全程不切换为中文语音** |
| **用户复述内容与素材完全无关** | AI 温和拉回：「这条素材讲的是 XX，你还记得其中哪一点吗？」。不判为合格复述（不计入内容传达），但**不阻断、不指责、不影响打卡** |

### 3.4 学习报告 / 对话文档

**功能描述**
每次语音复述会话结束后，AI 自动把对话转写为一份可回看、可分享的学习文档。这是**显性文字反馈的唯一载体**（对话中只做隐性重铸，见 §3.3④）。

**业务规则**

1. 文档在会话结束后**自动生成**，无需用户操作
2. 文档内容结构（顺序即优先级）：
   - **完成确认**：今日打卡状态、累计数据、本次学习时长
   - 素材信息（标题、来源、时长、难度、原平台链接、实际消费进度）
   - **做得好的**（`did_well`）—— 置于所有反馈之前
   - **更自然的说法**（`corrections`，**上限 2 条**）：`你说的 → 更自然的说法 → 中文说明`
     - ⚠️ **不使用语法术语命名**，不呈现语法知识点清单、错误类型统计、正确率等应试化内容（见 §3.3⑤）
   - **本次可以直接用的表达**（`useful_phrases`）：整句可复用表达，可勾选加入个人词表
   - **对话文字稿**（默认折叠）：完整语音对话的转写文本
3. **保存期限与合规处理**（⚠️ 此规则解决 §3.4 与 §7.1 的冲突，不可简化）：

   | 数据类型 | 保存策略 |
   |---------|---------|
   | **用户自己产生的内容**（对话文字稿、AI 反馈、表达清单） | **永久保存**在用户账号下 —— 这是用户的学习资产，不受第三方政策约束 |
   | **平台元数据**（素材标题、封面、时长、来源） | **只存素材 ID**，展示时从素材库实时读取；素材库自身按 §7.1 要求做 30 天刷新（见 §3.11） |
   | 素材已下架时 | 报告降级显示「该素材已不可用」，但**完整保留用户的学习内容** |

   > 直接把平台元数据快照永久存进报告，会违反 §7.1 的「非授权数据 30 天内必须删除或刷新」政策。

4. 报告可在「我的」中按时间 / 主题 / 素材检索
5. 分享能力 ⚙️ **首期默认**：支持生成**分享图片**（不做公开链接）。分享图内容为「素材标题 + 来源 + 本次的做得好的点与 2–3 条收获表达」，**不包含对话文字稿**（对话中可能含用户个人信息，如提到自己的工作、家庭）。个人词表与完整文字稿仅本人可见。<br>理由：图片分享成本最低、传播性足够，且天然规避了公开链接带来的隐私与内容审核成本。

### 3.4.1 个人词表

**功能描述**
沉淀用户在复述过程中积累的表达，供日后回看。

**业务规则**

1. **词条来源**：**仅来自学习报告中的「本次积累的词汇与表达」**，由用户**勾选加入**，不自动全量入库
   - 注意：§3.2③ 已确认「生词点查首期不做」，因此词表**不存在**从素材消费页直接添加词条的路径
2. **词条字段**：表达（英文）+ 中文释义 + 来自原素材的例句 + 来源报告链接
3. **列表能力**：按主题 / 时间筛选、搜索、删除、导出（纯文本或 CSV）
4. **去重**：同一表达重复加入时合并，保留多个例句（上限 3 条）
5. **容量上限**：单用户 2000 条，达到上限时提示用户清理
6. **首期不做**：记忆曲线复习、背诵测试、发音跟读 —— 见 §5.2

### 3.5 打卡机制

**功能描述**
用户完成一次完整流程（消费素材 → 与 AI 复述）即算完成一次打卡。

**业务规则**

**① 学习日与时间边界**（所有打卡、热力图、连续记录的计算基准）

- 「学习日」以**用户设备本地时间**为准
- **日界设在凌晨 4:00**，而非 0:00 —— 凌晨 1 点学习的用户主观上仍认为是「今天」，设在 4 点符合真实作息（且「睡前」是 §2 明确列出的核心场景）
- 即：某次学习发生在 3 月 2 日 02:30，计入 **3 月 1 日**的打卡
- 用户跨时区移动时，**不追溯修改已有记录**，仅影响此后的学习日归属
- 界面上凡涉及「今天」的表述，均以此定义为准

**② 打卡判定条件** ✅ 已确认

- 必须**完成一次复述会话**才算打卡。仅消费素材不算
- 判定条件是「有复述行为并结束了会话」，**不判定复述质量**——符合「只要学习了，就是胜利」
- 文字复述与语音复述等价
- 一天内多次完成：日历上该日标记为已打卡（不重复计天），但累计次数正常累加

**③「有复述行为」的最低成立条件**（必须定义，否则判定无边界）

- 成立条件：**至少完成 1 个有效轮次**
- 有效轮次 = 用户发出了可被识别为英文的内容，且 AI 给出了反馈
- 量化下界：识别出 **≥5 个英文词**（防止完全空转，如只说一个 "um" 就结束）
- **未达下界时不判失败、不提示失败**，而是鼓励式引导：「再试一次？一句话就够了」
- 会话中出现的 AI 服务故障轮次不计入有效轮次，也不消耗轮次配额（见 §3.3 异常分支）

> 设计权衡：下界设得太松（0 词也算）会让核心指标失真、打卡失去意义；设得太紧（要求完整复述）会踩「只要学习了就是胜利」的产品红线。5 个词是「确实说了一句话」的最低证据。

**④ 打卡机制形态** ✅ 已确认（**这是产品理念落地最关键的一处设计**）

采用「有连续记录，但断签不清零」的方案：

| 要素 | 设计 |
|------|------|
| 主视觉指标 | **累计打卡天数 / 次数**（只增不减） |
| 连续记录 | 保留展示，但**断签后不归零**，降级为「本月坚持 X 天」 |
| 补签 | **限时限量，且需真实学习换取**（详见 ⑤） |
| 热力图 | 强调「做过的日子」的正向着色，**不对空缺日做负向标记**（不用红色/深灰缺口强调） |
| 断签文案 | 邀请式而非指责式。例：「今天来看点新东西？」而非「你的连续记录即将中断！」 |

**明确禁止的设计**（违背核心理念）：

- ❌ 大号 streak 数字 + 归零动画
- ❌ 施压式推送（「你的 XX 天记录就要断了」）
- ❌ 用户间打卡排行榜 / 比较
- ❌ 断签惩罚（扣除积分、降级、失去权益）

> **设计依据**：行业经验表明 streak 是留存最强的单点功能，但断签羞耻会导致「全有全无」式弃用，这是打卡类产品的经典流失曲线。本方案保留正向激励、去掉惩罚机制，是留存与产品理念的平衡点。

**⑤ 补签规则**（⚠️ 关键：补签必须与 ② 的打卡判定规则一致，不可绕过）

| 规则项 | 定义 |
|-------|------|
| **兑换方式** | **必须通过完成一次真实学习闭环来兑换**，不是点击即得。即「今天多做一次，可以填上前两天的空」 |
| 可补范围 | 仅可补**最近 3 天内**的缺口日（不含今天） |
| 频次上限 | 每自然月 **3 次** |
| 学习时长归属 | 兑换所用的那次学习，其**时长计入实际完成日**（即今天）。被补的缺口日仅标记为已打卡，**不计入时长**，在热力图上显示为**最浅一档** |
| 累计次数归属 | 计入实际完成日 |
| 入口位置 | 数据页热力图中，点击可补范围内的空缺日出现「用今天的一次学习补上这天」 |
| 文案风格 | 邀请式，不出现「弥补」「挽回」「别让记录断掉」等施压表述 |

> **为什么这样设计**：原方案「无条件补签」与 ② 的「必须完成复述才算打卡」直接冲突——若点一下就能得到打卡，热力图便不再反映真实学习行为（用户可月底一次补满整月）。改为「需真实学习换取」后，热力图上每个格子背后都对应一次真实闭环，同时仍给偶尔忘记的用户一条不带羞耻感的补救路径。

**⑥ 提醒机制**

- 用户可自定义每日提醒时间；默认关闭或需用户主动开启
- 提醒文案风格：**内容驱动而非任务驱动**。例：「今天 KPOP 主题更新了 3 条新素材」优于「你还没有完成今日打卡」
- 提醒内容依赖 §3.1① 的订阅通知链路与 §3.1.1 的今日推荐数据
- **禁止**发送以连续记录为要挟的提醒（见 ④ 禁止清单）

### 3.6 数据统计

**功能描述**
可视化用户的坚持轨迹。

**业务规则**

**① 展示内容**

打卡日历 / 年度热力图、累计打卡天数、累计打卡次数、累计学习时长、主题分布、素材类型分布。

**② 热力图色深口径**（✅ 已确认：按当日累计学习时长）

- 色深按**当日累计学习时长**分档，而非打卡次数：

  | 档位 | 当日累计时长 | 视觉 |
  |------|------------|------|
  | 空缺 | 0 | 最浅中性灰（不使用任何彩色，视觉上退后，不构成提醒） |
  | 一档 | <5 分钟 | 最浅高亮色 |
  | 二档 | 5–15 分钟 | 浅 |
  | 三档 | 15–30 分钟 | 中 |
  | 四档 | >30 分钟 | 深 |

- **选择理由**：绝大多数用户每天只打卡 1 次，按次数分档会让热力图几乎全为同色，深浅维度失效；更严重的是会诱导用户「刷次数」——连做 3 条 3 分钟素材比认真做 1 条 20 分钟素材更「好看」，属反向激励。

**③ 学习时长的计算口径**（⚠️ 必须严格定义，否则时长口径会诱导「挂着不学」刷时长）

| 素材类型 | 计算方式 |
|---------|---------|
| 视频 / 音频 | 按**实际播放时长**累计，**暂停不计**；单条素材计入上限为该素材总时长（防止反复重播刷时长） |
| 文本 | 取「按字数估算的合理阅读时长（200 词/分钟）」与「实际停留时长」的**较小值** |
| 复述对话 | 计入实际交互时长（从首次录音到结束会话，扣除超过 2 分钟的无操作间隔） |

- **单日累计计入上限 60 分钟** —— 既防止极端值把色阶拉坏，也避免变成「卷时长」的产品
- 该口径同时用于「累计学习时长」统计

**④ 能力趋势**

✅ 已确认**首期只做行为数据，能力趋势放二期**。原因：能力趋势需要足够的历史样本才有统计意义，样本不足时呈现的波动会误导用户（甚至让用户误以为自己在退步，违背产品理念）。

**⑤ 统计口径原则**

所有统计以正向累积为主，**不呈现「缺勤率」「中断次数」等负向指标**。

### 3.7 社区

**功能描述**
✅ **已确认**：首期只做素材推荐流

**业务规则**

- 用户可将自己觉得好的素材 / 创作者分享到社区，附一句推荐语
- 其他用户可在社区流中浏览，**一键将该素材加入自己的学习流程**
- 支持点赞、收藏。⚙️ **首期默认不做评论**：评论会引入内容审核成本与社区氛围管理成本，且容易让社区从「帮人找到好内容」滑向「互相评价学习表现」，与社区的价值定位冲突。用户对素材的态度通过点赞与「一键开始学习」的行为数据表达即可
- 分享的素材经审核后可进入公共素材库——天然缓解素材库冷启动问题
- **设计意图**：直接强化核心理念「花时间找到既能让你学到东西、又能让你享受在其中的内容」。社区的价值定位是**帮人找到好内容**，不是**互相比较学习量**

### 3.8 账号与跨端同步

**业务规则**

**① 平台策略**

- **移动端 App 优先开发**，Web 端功能同步
- 移动端与 Web 端**功能对等**，同一账号数据完全同步：素材进度、复述会话、学习报告、打卡记录、个人词表、订阅主题（**录音不同步**，见 §3.3⑨）
- ⚙️ **首期默认**：Web 端语音交互能力与移动端**功能对等但入口权重不同**。Web 端同样支持语音复述，但因浏览器录音权限申请体验较重、且桌面环境常在办公场所（不便出声），**Web 端需把「文字复述」入口提到与语音入口同等显著的位置**（移动端以语音为主入口、文字为兜底）。两端的打卡判定与反馈质量完全一致。
- ⚙️ **首期默认**：首发平台为 **iOS + Android 双端同时**，Web 端随后。理由：目标用户年龄跨度 18–45 岁，国内该人群 Android 占比高，只发 iOS 会显著损失样本代表性，影响留存数据的可信度。若研发资源紧张需要收窄，建议改为 Android 先行而非 iOS 先行。

**② 注册墙位置**（⚠️ 直接决定「首次复述完成率」这一第一指标，不可含糊）

- **游客态可完成完整的首次学习闭环**：选主题 → 消费素材 → AI 复述 → 查看报告
- 注册要求**只在用户想要留存价值时才出现**：保存学习报告、查看数据页、加入个人词表、订阅主题、进入社区
- 注册后**游客期产生的数据自动迁移**（含首次的报告与打卡记录）
- 游客数据在本地保留 7 天；超期未注册则清理，并在清理前提示

> **设计依据**：把注册墙放在用户已获得价值之后。若在 onboarding 就要求注册，「首次复述完成率」会显著下降——而这正是文档 §1 定义的最关键前置指标。

**③ 登录方式**

- 首期支持：手机号验证码、Apple 登录（iOS 必备）、微信登录
- 不做密码体系（降低注册摩擦与安全成本）

**④ 会话保留与冲突策略**

| 项 | 规则 |
|---|------|
| 未完成会话保留期 | **7 天**。超期自动归档，不再出现在首页续接入口，但已产生的对话内容保留在报告历史中（标记「未完成」） |
| 续接入口 | 首页显示最近 1 个未完成会话；多个时只显示最新的，其余在「我的」中可见 |
| 中途退出 | **不做挽留弹窗**（挽留本质是施压，与理念冲突）。直接保留为未完成会话 |
| 多端同时打开同一会话 | 以**最后提交的轮次**为准；检测到冲突时提示「这个会话在其他设备上有更新」并提供刷新，不静默覆盖 |

### 3.9 用户水平与 onboarding

**功能描述**
确定用户的英语水平档，用于素材难度匹配、AI 反馈语言分级、复述模式默认值。

**业务规则**

**① 水平的来源**（⚠️ 全文多处依赖此值，必须定义）

- **自评为主**：onboarding 中三选一，映射到水平档：

  | 用户看到的选项 | 映射水平 |
  |--------------|---------|
  | 「能读懂简单句子，但听和说都吃力」 | A2 |
  | 「能看懂大部分内容，但说不太出来」 | B1 |
  | 「想挑战原速、真实语境的内容」 | B2 |

- **表现校准为辅**：系统根据历次复述表现，可**建议**调整水平档，但**绝不自动修改**——弹出温和提示「看起来这些素材对你来说有点简单了，要不要试试更有挑战的？」，由用户决定
- 水平档**始终可在「我的」页手动修改**
- 未设置时（如跳过 onboarding）：显示「未设置」，素材难度按「易」优先推荐，不做猜测

> **设计依据**：§7.3 已论证「自动分级准确率不足、标错会摧毁用户信任」。这个结论对用户水平标签同样成立——所以采用自评而非自动测评，且校准只建议不强制。

**② onboarding 流程**（2 步 + 直达内容，每步可跳过）

| 步骤 | 内容 | 文案要求 |
|------|------|---------|
| 1 | **水平自评**（上表三选一） | 用自然语描述而非 CEFR 代号。标题「你现在的英语，哪句更像？」，副标题说明用途与可改性 |
| 2 | **兴趣主题多选**（16 个预置主题） | 标题「想听点什么？」，副标题「选几个都行」——不设"至少选 N 个"的硬门槛 |
| 3 | **直接进入首次首页** | 呈现规则见 §3.1.1⑧ |

- 全流程**不要求注册**（见 §3.8②）
- 每一步都可跳过；全部跳过则进入冷启动推荐（见 §3.1.1⑤）
- **不做**产品功能引导浮层教学 —— 首次体验的目标是尽快完成一次闭环，而非理解产品全貌
- ❌ 文案禁止使用「请选择…」「欢迎！」「快去…吧」等指令式或欢呼式表述

**③ 首次复述的降门槛设计**（第一次开口是全流程最大的坎）

| 设计 | 规则 |
|------|------|
| AI 首句最短化 | 明确只要一句，如 "So, what was it about? One sentence is enough."（英文，见 §3.3⑦） |
| **给句子开头** | 直接提供 2 个句头（如 `It's about…` / `It talks about…`）。**给开头而非完整答案** —— 用户有话可接，但说出的仍是自己的话。**仅首次会话默认展开**，之后收进「提示」入口 |
| 操作提示只教一次 | 「按住说话」仅首次会话显示，第二次起不再出现 |

### 3.9.1 空态规范

**功能描述**
统一各页面在无数据时的呈现规则。空态是新用户必经的一屏，处理不当会被读成「功能坏了」或产生挫败感。

**两条硬规则**

1. **结构先于内容**：空态要**保留该模块的结构骨架**（如数据页仍画出全灰的热力图格子），**不得**替换为插画或纯文字。让用户立刻明白「这里以后会长什么样」，同时避免「功能异常」的误判
2. **只说事实 + 一个动作**：文案由「一句事实陈述」+「可选的一个动作入口」构成
   - ❌ 禁止鼓励句、感叹号、颜文字、表情（「快去学习吧！」「暂无数据哦～」）—— 属 AI 旁白，也构成施压
   - ❌ 禁止道歉式表述（「很抱歉，没有找到…」）

**各空态定义**

| 场景 | 呈现 |
|------|------|
| 数据页无记录 | 保留大数字位（显示 0，弱化配色）+ 副文案「完成第一次后这里会有记录」+ 全灰热力图骨架 + 动作「去学一条」 |
| 报告列表为空 | 「还没有报告」+「每次复述后会自动生成」（无动作入口，因为路径不在本页） |
| 词表为空 | 「还没有收藏的表达」+「在学习报告里可以收藏」 |
| 主题搜索未命中 | 「还没有 XX 的素材」+「有了就通知你」+ 动作「订阅这个主题」+ **分区展示相近主题**（标题「试试这些」，与订阅入口视觉分离，不构成静默降级，见 §3.1①） |
| 社区无内容 | 「还没有人推荐」+ 动作「推荐一条」 |
| 未完成会话已过期 | 不做空态提示，直接不显示续接入口（静默消失，见 §3.8④） |

### 3.11 素材运营后台（首期必需）

**功能描述**
素材库的建设、审核与维护工具。**这不是配套工具，是首期必需交付物** —— 按 §7.2 的配额结论，素材供给完全依赖此后台，没有它产品首期就是空壳。

**业务规则（首期最小集）**

| 能力 | 说明 |
|------|------|
| **白名单源管理** | 维护可信的 YouTube 频道 / 播客 RSS 源 / 文本站点清单；每个源需记录**分发许可确认状态**（播客源尤其重要，见 §7.1） |
| **批量入库** | 通过低成本接口（`playlistItems.list` 等，1 unit/次）批量拉取候选素材，**避免依赖 `search.list`**（100 unit/次，见 §7.2） |
| **审核工作台** | 按 §3.1④ 的 7 条标准逐条核验；状态机：`待审核 → 已通过 / 已拒绝 / 需复核` |
| **难度与语速标注** | **自动预标 + 人工复核**。自动预标给出建议档位，人工确认或修正后才可上线 |
| **元数据 30 天刷新** | ⚠️ **政策强制**（见 §7.1）：定时任务刷新或删除超过 30 天的平台元数据 |
| **下架检测** | 定期检测素材在原平台的可用性；已下架的素材下线并触发替代推荐（见 §3.2 页面状态） |
| **短素材库存告警** | 任一主题的「3 分钟以内素材」库存 < 2 条时告警（对应 §3.1③ 的硬规则） |
| **主题上线门槛校验** | 校验主题是否满足「≥30 条素材且 ≥2 条短素材」（见 §3.1①） |
| **主题订阅需求看板** | 汇总用户订阅但尚无素材的主题，按订阅人数排序，指导素材补充优先级；主题达标上线时触发通知（见 §3.1①） |
| **社区分享素材的审核** | 社区分享的素材进入同一审核流程后才可进入公共素材库（见 §3.7） |

**上线库存门槛**：首期上线前，16 个预置主题每个需满足「≥30 条素材，其中 ≥2 条 3 分钟以内短素材」。

## 4. 页面与交互

### 4.0 导航结构

7 个页面**不是并列关系**。分为两层：

**底部 Tab（4 个 · 并行目的地）**

| Tab | 页面 |
|-----|------|
| 首页 | §4.1 主页面 |
| 数据 | §4.5 数据页 |
| 社区 | §4.6 社区页 |
| 我的 | §4.7 我的页 |

**流程内二级页（3 个 · 栈式推入，有序流程）**

素材消费页（§4.2）→ AI 复述对话页（§4.3）→ 学习报告页（§4.4）

- 这 3 页构成一条有序流程，**不是并行目的地**
- ⚠️ **进入这 3 页时必须隐藏底部 Tab 栏** —— 复述过程中底部露出 Tab 栏会诱导用户中途跳走，直接伤害核心转化
- 仅提供「返回」与流程内的前进操作
- 中途退出的处理见 §3.8④（保留为未完成会话，不做挽留弹窗）

### 4.1 主页面（Home / 今日）

- **页面用途**：进入学习闭环的唯一主入口
- **核心元素**：
  - 今日打卡状态条（正向表述）
  - **今日推荐素材卡片列表**（3–5 条，业务规则见 §3.1.1）
    - 卡片字段以 §3.1「输入/输出」表为唯一真值：标题、**中文一句话摘要**、**封面图**、类型图标、时长、难度档、语速档、来源平台
    - **首卡支持一键直达消费页**（无需先选主题）
  - **「3 分钟速通」标记**——置顶标注在短素材卡片上，防畏难关键位
  - 主题输入框 + 预置主题卡片区（16 个，见 §3.1①）
  - 未完成会话的续接入口（若有，见 §3.8④）
  - 「换一批」入口（每日 3 次，见 §3.1.1⑥）
- **用户操作流程**：
  - **最短路径（1 次决策）**：点击今日推荐首卡 → 直接进入消费页
  - 常规路径：选主题 → 浏览素材 → 选一条进入消费
- **状态与反馈**：首次使用的引导态、素材加载中、主题未命中态（含订阅入口）、主题输入异常态（无意义/敏感/多主题，见 §3.1⑥）、有未完成会话的续接态、封面图缺失的占位降级

### 4.2 素材消费页

- **页面用途**：承载素材消费，并引导进入复述
- **核心元素**：播放器 / 阅读器（视频需为官方嵌入播放器，不可遮挡）、字幕或文稿对照区、倍速控制（四档常驻，不藏入菜单）、消费进度、来源与原平台跳转链接、字号调节、**「进入口语复述」CTA**
- **用户操作流程**：播放或阅读 → 按需调速、看字幕 → 点击完成进入复述
- **状态与反馈**：加载中、播放失败、素材已下架（推荐替代素材）、字幕不可用

### 4.3 AI 复述对话页

- **页面用途**：承载**语音**复述与 AI 语音回应的实时对话。核心是「像在跟人说话」，不是「在用聊天软件」
- **核心元素**：
  - **语音状态区（页面视觉重心）**：呈现当前是谁在说、是否在听 —— 不用聊天气泡堆叠作为主界面
    - 当前话语以**英文**显示；中文翻译**默认不显示**，仅在用户点击「看中文」时展开（见 §3.3⑦②）
  - 通话式录音控件（说话 / 聆听 / 处理三态清晰可辨）
  - **实时文字稿区**（辅助，可折叠）：同步转写双方话语；AI 的话为英文，中文翻译默认隐藏
  - 引导模式下的**英文**句子开头提示（可听可看）
  - 「看中文」按钮（弱视觉，按需展开当前话语的中文翻译）
  - 模式切换入口（引导 / 自由）
  - 「改用文字复述」入口（次级，见 §3.3⑧）
  - 「结束对话」按钮
  - 轮次指示（弱视觉）
- ⚠️ **不在本页呈现显性纠错清单** —— 对话中只做隐性重铸（§3.3④），文字纠错在报告中呈现
- **用户操作流程**：听 AI 提问 → 说英文回应 → 听 AI 自然回应与追问 → 循环 → 结束对话
- **状态与反馈**：麦克风未授权（引导授权 + 文字兜底）、正在说话、正在聆听、正在处理、识别失败（可重说）、**语音合成失败（降级为文字气泡）**、**用户打断 AI**、**环境噪音过大**、**长时间静默**、网络中断（保留对话）

### 4.4 学习报告页

- **页面用途**：回看单次学习成果，**也是显性文字反馈的唯一载体**
- **核心元素**（顺序即优先级，见 §3.4②）：
  - **完成确认区**（打卡状态 + 累计数据 + 本次时长）——置于页首
  - 素材信息（含实际消费进度）
  - **做得好的**
  - **更自然的说法**（上限 2 条，`你说的 → 更自然的说法 → 中文说明`）
  - **本次可以直接用的表达**（可勾选加入词表）
  - 对话文字稿（默认折叠）
  - 分享按钮（生成图片，不含文字稿）
  - 底部动作：**必须包含明确的退出路径**（见 §4.8）
- ⚠️ **禁止**呈现语法知识点清单、错误类型统计、语法正确率等应试化内容（§3.3⑤）
- **状态与反馈**：生成中、生成失败（保留文字稿，可重试生成）、部分反馈缺失（AI 服务曾故障时）

### 4.5 数据页

- **页面用途**：可视化坚持轨迹
- **核心元素**：月历 / 年度热力图、累计天数与次数、累计时长、主题分布图、素材类型分布
- **状态与反馈**：无数据的空态（鼓励式文案 + 引导开始首次学习）

### 4.6 社区页

- **页面用途**：发现别人推荐的好内容
- **核心元素**：素材推荐流（素材卡 + 推荐语 + 推荐人）、「一键开始学习」按钮、点赞收藏、发布推荐入口
  - 素材卡字段与 §3.1「输入/输出」表一致（含封面图与中文摘要）
- **状态与反馈**：空态、加载中、内容审核中提示

### 4.7 我的页

- **页面用途**：个人设置与历史沉淀
- **核心元素**：
  - 头像 + **水平标签**（来源与可修改性见 §3.9①）
  - 学习报告历史列表（可按时间/主题/素材检索）
  - 个人词表入口（见 §3.4.1）
  - 已订阅的主题（可取消）
  - **报告解释语言开关**（中文 / 英文，仅影响报告中的书面解释，见 §3.3⑦③）—— **不提供 AI 语音语言开关**，语音永远英文
  - 提醒时间设置
  - **录音数据管理**（删除录音 / 删除学习记录，两者语义不同，见 §3.3⑨）
  - 隐私设置（含「录音用于模型训练」的独立开关，默认关闭）
  - 字号调节
  - 账号与登录管理

### 4.8 交互设计原则

- **UI 清晰简洁，适配大部分用户**：避免过度装饰与复杂手势
- **核心路径决策数**（可测口径）：
  - 「决策」定义为**用户必须做出选择才能继续的节点**（不含滚动、播放等非选择性操作）
  - 从冷启动到进入素材消费页 **≤2 次决策**（今日推荐首卡可一键直达，主题选择非必需）
  - 从消费页到会话结束 **≤2 次决策**
- **跨代兼容（对应 18–45 岁用户跨度）**——本节为该组要求的唯一真值来源：
  - **主题选品**：不能只做年轻向主题（KPOP、游戏），须同时覆盖职场、商业财经、时事、健康、人文历史等 **30 岁以上用户**更关注的主题（已落实为 §3.1① 的 16 个主题清单）
  - **UI 无障碍**：正文字号可调；文字对比度满足无障碍要求；点击热区不小于 44×44pt；关键信息不依赖细小图标或颜色单独传达（需有文字冗余）
  - **场景权重**：年轻用户碎片时间更多，**30 岁以上用户**的深度消费场景（周末、固定通勤时段）权重更高，两类场景需同等重视
- **不使用强游戏化视觉语言**：不用夸张动画、卡通吉祥物、密集音效反馈——对偏成熟用户易造成幼稚感，与「专业教练」定位冲突
- **避免「AI 生成感」的版式**（⚠️ 硬性要求）：
  - ❌ **禁止**整页由均质圆角卡片堆叠构成 —— 这是 AI 生成界面最典型的特征，会让产品显得廉价、模板化
  - ✅ 建立**明确的视觉层级差异**：主信息可用无边框的大字号直接排版、次信息用分割线或留白区隔、仅真正需要独立成块的内容才用卡片
  - ✅ 同一屏内**避免出现 3 个以上相同规格的圆角容器**；若信息本身是列表，用分割线或紧凑行式而非逐条卡片
  - ✅ 优先用**留白与字号对比**建立层次，而非用边框和底色
  - ✅ **内容直接贴在背景上**：正文区域不套容器，封面图是页面中唯一需要圆角的元素类型
  - ✅ **每屏只设一个视觉焦点**（通常是一个大字号数字或标题），其余全部降级 —— 多个数据并列等于没有重点
  - ❌ **禁止用 emoji 充当功能图标**（如 🎙 ◉ ▦）—— 统一使用线性图标。emoji 仅可出现在极少数标签中
  - ✅ 高亮态优先用**字重与颜色**（如加粗变深），而非底色块

- **UI 文案规范**（⚠️ 硬性要求，去「AI 味」的根本手段）：

  界面不解释自己。以下四类是「AI 味」的主要来源，逐条禁止：

  | 禁止 | 说明 | 反例 → 正例 |
  |------|------|------------|
  | **界面替 AI 说话** | 鼓励、表扬、评价属于**教练的语音**，不属于界面文案。界面用数据陈述事实 | 「你做到了」→ 直接显示「6 分钟 · 今天第 3 次」 |
  | **用完整句子当 UI 文案** | 按钮与标签用**名词或短动词**（≤4 字优先） | 「结束对话，看这次的总结」→「结束」；「卡住了？让教练给个开头」→「提示」 |
  | **界面里放产品宣言** | 理念通过产品行为传达，不写在界面上 | 「找到好内容，比逼自己坚持更有用」→ 删除 |
  | **解释显而易见的东西** | 结构自明的内容不加标签、不加图例 | 热力图不加图例与「最近 6 周」；「你说的 → 更自然的说法」不加标题 |

  **附加规则**：

  - **区块标签能省则省**：位于页面顶部或结构自明的分组不加标签
  - **操作提示只教一次**：如「按住说话」仅首次显示
  - **数值优先于形容**：用「29 次」而非「已完成多次」
  - **不评论用户的行为或缺勤**：如数据页缺勤处只给动作入口「去补卡」，不写「前两天空着」「你有 8 天没学习」
  - ❌ 禁止感叹号、颜文字、表情式语气词（「哦～」「啦」「呢」）
  - ❌ 禁止「为你」「帮你」等 AI 口吻（「今天为你找到」→「今日推荐」）
  - ⚠️ **唯一例外**：首次首页的「两分半，说一句就算完成」保留为完整句 —— 该处降低门槛的收益大于代价（见 §3.1.1⑧）
- **每一页必须有明确的退出路径**（⚠️ 新增硬性要求）：
  - 任何页面的底部动作区**不得只提供「继续深入」类操作**，必须包含一个让用户离开当前流程的出口（返回首页 / 完成 / 稍后再说）
  - 退出操作可以是次级视觉，但**必须可见**，不得只依赖系统返回手势或顶部返回箭头
  - 退出时**不弹挽留**（见 §3.8④）
- **配色体系**：以**白色（夜间为黑）为基础色**，大面积留白；低饱和马卡龙色仅作为**高亮层**用于标签、状态点、热力图等小面积功能位（参考 Notion 高亮体系）。详见 §4.9
- **主流程零阻断**：任何异常状态都必须提供继续前进的路径，不做死胡同
- **正向表述优先**：所有文案避免负向、施压、比较性表述

### 4.9 视觉规范

> 本节为**可交付开发的量化规范**。所有色值给出浅色 / 深色两套，首期同时交付双主题。
> **⚠️ 浅色为主要目标、深色为第二目标**：设计评审、原型、走查均以浅色为基准；深色需保证可用与达标，但视觉打磨优先级低于浅色。
> 已确认的四项基调：正文基准 **16px / 行高 1.7** · 卡片圆角 **10px** · 动效**克制** · 双主题同时交付。

#### 4.9.1 基础色（大面积，占屏幕 70% 以上）

| 用途 | 浅色 | 深色 | 说明 |
|------|------|------|------|
| 底色 Base | `#FFFFFF` | `#16181C` | 页面底色 |
| 次级面 Surface | `#F7F8F9` | `#1E2126` | 输入框、折叠区、弱区隔背景 |
| 静默 Muted | `#EDEFF2` | `#262A30` | **热力图空缺日**、进度条底、占位块 |
| 主文字 | `#1A1D21` | `#ECEEF0` | 标题、正文、大数字（对比度 ≥13:1） |
| 次级文字 | `#5B6470` | `#9AA3AE` | 说明、摘要、中文解释（对比度 ≥5.5:1） |
| 三级文字 | `#8B949E` | `#6B747E` | 元信息、时长、来源。**不得用于正文** |
| 分割线 / 描边 | `#E3E6EA` | `#2E333A` | **层级的主要载体** |

**原则**：大面积区域只用基础色与留白，不铺彩色底。

#### 4.9.2 马卡龙高亮层（仅小面积功能位）

| 色相 | 浅底 / 深底 | 浅字 / 深字 | 用途 |
|------|-----------|-----------|------|
| **薄荷绿**（主色） | `#E8F5EE` / `#1E3A2E` | `#2E7D5B` / `#5FCF9E` | 打卡完成、热力图、主按钮、难度「易」 |
| **雾霾蓝**（辅色） | `#E9F1FA` / `#1C3348` | `#2C6FA8` / `#7DB8E8` | 素材类型标签、「更自然的说法」、链接 |
| **丁香紫**（点缀） | `#F0EBFA` / `#2C2542` | `#6B4FA8` / `#B49CE8` | AI 语音状态、麦克风、报告标识 |
| **奶油杏**（强调） | `#FBF2E4` / `#3A3020` | `#A87A28` / `#E0B463` | **仅**「3 分钟速通」标签与字幕当前句高亮 |
| **浅珊瑚**（错误） | `#FCEBEA` / `#3D2422` | `#C0453C` / `#E8837B` | **仅系统错误** |

**两条颜色硬规则（与产品理念绑定，验收可核）**

- **珊瑚 / 红色系只允许出现在系统错误提示中**（网络失败、加载失败）。断签、缺勤、未完成一律用「静默 `#EDEFF2`」—— 否则热力图空缺会变成一片刺眼的红，正是要规避的 PUA 感
- **五个高亮色的浅底色不得用于大面积铺底**，仅用于标签、状态点、气泡、热力图格子等小面积功能位

> ⚠️ 马卡龙色系容易被做成偏可爱的风格，与 §4.8「不使用强游戏化视觉语言」冲突。规避方式是**靠克制的字重与充足留白**建立专业感，而非增加插画或吉祥物。

#### 4.9.3 热力图五档

| 档位 | 当日累计学习时长 | 浅色 | 深色 |
|------|----------------|------|------|
| 空缺 | 0（未学习） | `#EDEFF2` | `#262A30` |
| 一档 | < 5 分钟 | `#D6EDE0` | `#224534` |
| 二档 | 5–15 分钟 | `#A8DCC2` | `#2F6349` |
| 三档 | 15–30 分钟 | `#6BC49B` | `#3F8A63` |
| 四档 | > 30 分钟 | `#2E7D5B` | `#5FCF9E` |

> ⚠️ **空缺档不属于绿色色阶**：用中性灰而非「最浅的绿」。若空缺是浅绿，用户会读成「我这天只学了一点」；用中性灰才读成「这天没有记录」。
>
> ⚠️ **不提供色阶图例**：热力图的深浅含义为通用认知，无需在界面上解释（见 §4.8 UI 文案规范「解释显而易见的东西」）。用户可点击单个格子查看当日详情。

#### 4.9.4 字号阶梯（基准 16px）

| 级别 | 字号 | 字重 | 字距 | 行高 | 用途 |
|------|------|------|------|------|------|
| Display | 28px | 700 | -0.02em | 1.25 | 页面主标题（如「今天完成了」） |
| Title | 22px | 700 | -0.015em | 1.3 | 区块主标题 |
| Subtitle | 18px | 650 | — | 1.4 | 素材标题 |
| Body L | 17px | 400 | — | 1.7 | 复述页 AI 当前话语 |
| **Body（基准）** | **16px** | 400 | — | **1.7** | 正文、中文解释 |
| Secondary | 15px | 400 | — | 1.6 | 说明、摘要（次级文字色） |
| Caption | 13px | 400 | — | 1.5 | 元信息（三级文字色） |
| Label | 11px | 700 | 0.1em | — | 小节标签（大写） |
| Numeral | 26px | 700 | — | 1.1 | 大数字（等宽 + `tabular-nums`） |

- **级差刻意做大**（28→22→18→17→16→15→13→11）：层级要靠字号一眼看出，这是「去掉卡片与边框后仍能建立层级」的前提。级差若只有 1–2px，去掉边框后页面会糊成一片
- **字号可调**（§4.8 无障碍要求）：用户可在「我的」页切换 标准 / 大 / 特大，对应基准 **16 / 18 / 20px**，其余级别按比例缩放
- **所有数字**（打卡天数、时长、进度）统一用等宽字体 + `tabular-nums`，变化时不跳动

#### 4.9.5 间距体系（4px 基准栅格）

| Token | 值 | 用途 |
|-------|-----|------|
| space-1 | 4px | 图标与文字间隙 |
| space-2 | 8px | 标签间距、列表行内间隙 |
| space-3 | 12px | 列表行上下 padding |
| space-4 | 16px | 页面左右边距、卡片内 padding |
| space-5 | 24px | 区块之间（同一组内） |
| **space-6** | **32px** | **大区块之间（分割线上下）** |
| space-7 | 48px | 页首留白、底部动作区上方 |

- ⚠️ **space-6（32px）是本规范最关键的数值**：报告页与数据页去掉卡片后，层级完全靠「分割线 + 32px 上下留白」建立。压到 16–20px 页面会重新拥挤（失去「简洁」），放到 48px 以上一屏装不下内容
- 所有间距必须是 **4 的倍数**，不允许出现 7px、13px 这类值

#### 4.9.6 圆角

| 用途 | 圆角 |
|------|------|
| 卡片 / 弹层 / 输入框 / 按钮 | `10px` |
| 标签 / 徽章 | `6px` |
| 热力图格子 | `3px` |
| 头像 / 麦克风按钮 | `50%` |
| 进度条 / 药丸标签 | `999px` |

#### 4.9.7 阴影（几乎不用 —— 去「AI 生成感」的关键）

- **不使用阴影**：列表行、分区块、标签、信息区 —— 一律用分割线或留白
- **仅两处允许阴影**：
  - 浮层与弹层：`0 4px 16px rgba(0,0,0,.08)`
  - 麦克风主按钮：`0 2px 8px rgba(0,0,0,.06)`
- 深色模式下阴影几乎不可见，改用**描边 `#2E333A`** 建立层次

> **理由**：「圆角卡片 + 柔和阴影」的组合正是 AI 生成界面最典型的特征（见 §4.8）。去掉阴影后，页面必须靠排版本身站住。

#### 4.9.8 动效（克制）

| 场景 | 时长 | 缓动 | 效果 |
|------|------|------|------|
| 页面切换（栈式推入） | 280ms | `cubic-bezier(.22,1,.36,1)` | 横向滑入 |
| 按钮按下 | 120ms | `ease-out` | `scale(.98)` + 轻微变暗 |
| 折叠区展开 / 收起 | 240ms | `cubic-bezier(.22,1,.36,1)` | 高度过渡 |
| AI 语音声波 | 循环 | `ease-in-out` | 条形高度起伏（**唯一常驻动效**） |
| 录音状态切换 | 180ms | `ease-out` | 颜色与图标渐变 |
| 内容加载 | — | — | 骨架屏，**无 shimmer 流光** |

**明确禁止的动效**：

- ❌ 打卡完成的庆祝动画、撒花、弹跳（§4.8 禁止强游戏化视觉）
- ❌ 数字滚动递增效果（累计次数、天数直接显示最终值）
- ❌ 元素依次淡入的入场动画（典型模板感）
- ❌ 任何 streak 相关的强调动效，尤其归零动画（§3.5④ 已禁止）
- ❌ 加载 shimmer 流光

#### 4.9.9 关键组件规格

**按钮三级**

| 级别 | 样式 | 用途 |
|------|------|------|
| 主按钮 | 薄荷绿实底 + 白字 + 16px/650 + 圆角 10 + padding 13 | 页面主操作 |
| 次级按钮 | 透明底 + 描边 `#E3E6EA` + 主文字色 + 15px/600 | 并列选项（如「继续看」/「就现在复述」） |
| **退出操作** | **下划线文字** + 次级文字色 + 14px | 退出路径（**不做按钮块**，避免与继续操作视觉等重） |

**标签**：12px / 600 / 圆角 6px / padding 3–8px。中性信息（如时长）用次级面底色，**不占用高亮色**。

**分割线分区（替代卡片的标准模式）**：`Label 11px` → 内容 → `分割线 + space-6 上下留白` → 下一个 `Label`。无边框、无底色、无阴影。

## 5. 非目标

分两类，性质完全不同，不可混淆：**5.1 是永久禁区，5.2 是二期候选**。

### 5.1 政策禁止（永久不做，依据见 §7.1）

| 不做的事 | 依据 |
|---------|------|
| 音视频离线下载 / 缓存播放 | §7.1 |
| 用户输入触发第三方平台实时搜索 | §7.2（配额不可行） |
| 自行抓取或下载第三方平台的字幕正文 | §7.1（需内容所有者授权） |
| 遮挡 / 改造播放器、屏蔽广告、移除归属标识 | §7.1 |
| 订阅付费才能观看素材 | §7.1（禁止对嵌入播放器观看收费） |

### 5.2 首期不做（二期候选）

| 不做的事 | 原因 | 进入二期的前置条件 |
|---------|------|------------------|
| 发音音素级评分 | 首期聚焦核心闭环 | 核心闭环留存达标后 |
| 生词点查 | 避免分散核心闭环精力 | 用户明确反馈需求 |
| 个性化专项练习 | 需历史数据积累才有效 | 用户平均完成 ≥20 次会话 |
| 能力趋势图表 | 样本不足时波动会误导用户 | 用户平均完成 ≥20 次会话 |
| 词表记忆曲线复习 / 背诵测试 | 首期词表只做沉淀 | 词表使用率达标后 |
| 社区评论 | 规避审核成本，防止滑向互相比较 | 社区推荐流形成正向氛围后 |
| 学习报告公开链接分享 | 隐私与内容审核成本 | 隐私脱敏方案成熟后 |

### 5.3 因准确率不足而排除

| 不做的事 | 原因 |
|---------|------|
| CEFR 六级精细分级（素材难度） | 自动化准确率仅约 62.6%，标错会摧毁用户信任、放大畏难流失。改做三档，见 §7.3 |
| 自动测评用户英语水平 | 同上论证对用户标签同样成立。改做自评 + 建议式校准，见 §3.9① |

### 5.4 理念性排除（与产品理念冲突）

| 不做的事 | 冲突的理念 |
|---------|-----------|
| 自制英语教材 / 课程体系 | 「Content is king，不自制教材」 |
| 用户间学习量排行榜 / 比较 | 「不要 PUA 自己」 |
| streak 归零惩罚与施压式推送 | 同上 |
| 复述质量门槛（不达标不算打卡） | 「只要学习了，就是胜利」 |
| 中途退出的挽留弹窗 | 挽留本质是施压 |

## 6. 验收标准

### 主题输入与素材检索

- [ ] 16 个预置主题全部上线，且每个均满足「≥30 条素材、其中 ≥2 条 3 分钟以内短素材」的门槛
- [ ] 输入预置主题名、别名、近义词、常见错拼均能返回相关素材
- [ ] 存在「疑似命中 → 二次确认」这一档，不是只有命中/未命中两态
- [ ] **任意主题返回的素材列表中，必含至少 1 条 3 分钟以内的素材，且被显著标记**
- [ ] 短素材耗尽时的跨主题补位**有显式来源标注**，不静默替换
- [ ] 素材列表包含长短混排的多个时长档
- [ ] 每条素材卡片按 §3.1 字段表完整展示：标题、**中文摘要**、**封面图**、类型图标、时长、难度档、语速档、来源平台
- [ ] 封面图或摘要缺失时有占位降级，不显示为空白
- [ ] 输入未命中主题时，明确告知且提供订阅入口，**不返回不相关素材**
- [ ] 无意义输入、敏感词输入走独立提示，**不进入订阅流程**
- [ ] 多主题混合输入时提示择一，不做交集检索
- [ ] 订阅的主题达标上线时，订阅者收到通知
- [ ] 素材库中不存在含非英语字幕轨的音视频素材
- [ ] 素材库中不存在需登录 / 付费才能访问的素材

### 今日推荐

- [ ] 每日推荐 3–5 条，必含至少 1 条 3 分钟以内短素材并置顶标记
- [ ] **首卡可从主页一键直达消费页**，无需先选主题
- [ ] 已完成消费的素材不再出现在今日推荐中
- [ ] 未完成消费的素材可再次出现，并标记「上次看到 X 分钟」
- [ ] 冷启动用户（无主题、无历史）能获得通用高质量短素材，不出现空列表
- [ ] 「换一批」每日可用 3 次

### 素材消费

- [ ] 视频通过官方嵌入播放器播放，播放器控件、广告、归属标识均未被遮挡或改造
- [ ] 无任何音视频下载 / 本地缓存 / 离线播放能力
- [ ] 播客音频由原始 CDN 直接流式播放
- [ ] 提供「在原平台打开」的深链跳转
- [ ] 支持倍速播放；字幕或文稿在来源提供时可对照展示
- [ ] 素材已下架时给出明确提示并推荐替代素材
- [ ] 用户可在任意消费进度下进入复述环节（无进度门槛）
- [ ] 进度 <70% 时进入复述有温和提示但**不阻断**，且默认不预选任何选项
- [ ] 未完成消费的素材记录断点，下次可从断点继续

### AI 语音复述与反馈

**交互形态（语音对话）**

- [ ] **AI 以语音回应**，不是「用户说话 → AI 输出文字」的半程形态
- [ ] 用户可在 AI 说话时**打断**，AI 立即停止并转入聆听
- [ ] 对话过程中同步生成文字稿，且文字稿是**辅助区域而非主界面**
- [ ] 复述页**不是打字聊天窗口**：语音为默认且视觉主导的输入方式
- [ ] 语音合成失败时降级为文字气泡，对话不中断
- [ ] 环境噪音导致反复识别失败时，建议改用文字复述而非无限重试
- [ ] 用户长时间静默时：引导模式主动给语音提示，自由模式等待更久

**纠错的实用导向**

- [ ] **不影响理解的语法细节不纠错**：三单 -s、冠词、可数不可数、时态小偏差、介词细微误用均不出现在纠错项中
- [ ] 中式英语直译、影响理解的用词错误**必纠**
- [ ] `corrections` 数组长度**由程序强制 ≤2**，超出被截断
- [ ] 纠错项给出**可直接复用的整句表达**，而非语法规则说明
- [ ] **报告与对话中均不出现语法术语**（主谓一致、动名词、时态、冠词、定语从句等）
- [ ] **不呈现**语法知识点清单、错误类型统计、语法正确率等应试化内容
- [ ] 应试化禁用词表校验生效：命中语法术语或评分类表述时重新生成

**对话中的隐性反馈**

- [ ] **对话中不打断用户纠正语法**
- [ ] 对话中 AI 采用 recast（自然回应里带出正确说法），不念语法术语
- [ ] AI 每次回应先承接内容、再自然重铸，重心在推进对话
- [ ] 仅当错误导致理解失败时，AI 才显式确认「你是说……吗？」
- [ ] **复述页不呈现显性纠错清单**（显性纠错只在报告中）

**通用**

- [ ] 首次使用默认进入引导模式；用户可随时切换模式
- [ ] 引导模式下，用户卡住时 AI 主动提供句子开头提示
- [ ] AI 返回结构化字段（did_well / corrections / useful_phrases / encouragement），由客户端渲染
- [ ] 风格禁用表述校验生效：命中打分类/比较类/努力程度类表述时重新生成
- [ ] 20–30 条固定评测集全部通过，须含「轻微语法错误但表达清楚→不纠错」与「中式英语但语法正确→必纠」两类用例
**语言环境（§3.3⑦）**

- [ ] **AI 语音全程英文，无任何中文**（含开场、提问、提示、鼓励、理解确认），无中文括注
- [ ] 无中英夹杂在同一句内
- [ ] 分级方式为**调节英文难度**（A2 短句慢速 / B1 日常 / B2 自然语速），**不是切换到中文**
- [ ] 用户听不懂时 AI **用更简单的英文重说**（rephrase），不切换为中文语音
- [ ] 用户说中文时 AI 仍用英文回应并给英文句式开头；连续 2 轮后仍不切换中文语音
- [ ] **对话文字稿中的中文翻译默认隐藏**，需点击「看中文」才展开
- [ ] 报告中的书面解释为中文（可在「我的」页切换为英文）
- [ ] **不存在「AI 语音语言」设置开关**
- [ ] 复述过短或质量低时，AI 仍给出反馈且不拒绝判定完成
- [ ] 会话在达到轮次上限后由 AI 主动引导收尾，不会无限延长
- [ ] 用户可在任意时刻主动结束会话
- [ ] 麦克风未授权时，引导授权并同时提供文字复述入口
- [ ] 文字复述可完成完整闭环，且打卡判定与语音复述等价
- [ ] 语音识别失败时可重录或转文字输入
- [ ] 网络中断后已有对话不丢失
- [ ] **AI 服务失败**时自动重试 2 次；仍失败则该轮不消耗轮次，且已有 ≥1 有效轮次的会话仍可结束并计打卡

## 7. 硬约束（不可违背，直接影响功能实现）

> 本节内容源自素材来源平台的政策与配额限制，是**功能设计的前置约束**，非建议。违反将导致产品被平台封禁或面临法律风险。

### 7.1 第三方内容使用约束

依据 [YouTube API 服务开发者政策](https://developers.google.com/youtube/terms/developer-policies)：

| 约束 | 政策原文要点 |
|------|-------------|
| 禁止下载 / 缓存 / 转存音视频 | 未经书面批准，不得 "download, import, backup, cache, or store copies of YouTube audiovisual content" |
| 禁止离线播放 | 不得 "make content available for offline playback" |
| 禁止抓取 | 不得 "scrape YouTube Applications" 或使用抓取来的数据；必须通过官方 API 获取数据 |
| 禁止改造播放器 | 不得 "modify, build upon, or block any portion or functionality of a YouTube player" |
| 禁止屏蔽广告 | 不得 "modify, interfere with, replace, or block advertisements placed or served by YouTube" |
| 禁止移除归属 | 不得遮挡平台提供的归属标识，不得移除播放器内的链接 |
| 禁止对观看收费 | 不得 "charge users to watch content in an embedded YouTube player" |
| 元数据缓存期限 | 非授权数据 "after 30 calendar days, the API Client must either delete or refresh the stored data" |
| Made For Kids | 必须查询每个嵌入视频的 Made For Kids 状态并对其关闭追踪 |
| 禁止混排搜索结果 | 不得把非该平台来源的结果混入并呈现为其搜索结果 |
| 归属展示 | 展示其内容的页面必须明确标示来源平台 |

**播客方面**：RSS 是公开分发协议，但**不等于任意再分发授权**。部分内容方（如 Radio-Canada）已关闭 RSS 并主张仅授权自有平台分发；部分托管商（如 RSS.com）明确要求音视频文件不得被缓存、必须由其 CDN 直接分发、不得预加载。**素材入库时需逐源确认分发许可**。

### 7.2 检索配额约束

YouTube Data API 默认配额为每 Google Cloud 项目每天 **10,000 units**，其中：

- `search.list` = 100 units/次 → 即**全平台每天仅约 100 次搜索**
- `videos.list` / `channels.list` / `playlistItems.list` = 1 unit/次
- `captions.download` = 200 units/次，且需视频所有者 OAuth 授权
- **无自助付费提额通道**，仅可提交审核表申请，周期长且常被拒或降额

**直接结论**：面向用户的实时自由搜索不可行。必须采用「预建素材库 + 语义匹配」，并通过 `playlistItems.list`（1 unit）等低成本接口做批量入库与更新，而非依赖 `search.list`。

### 7.3 分级精度约束

自动化 CEFR 分级的准确率上限：传统可读性公式单指标最高约 41.8%（Flesch Reading Ease 仅 12.7%，低于随机基线）；基于 24 个语言复杂度特征的模型在三大级（A/B/C）约 82.6%、六级细分约 62.6%。

**直接结论**：难度分级只做三档，不做六级细分。

### 从布局设计中提炼的设计原则

这些原则已升级为 §4.8 的硬性要求，此处记录其来源：

1. **无卡片堆叠** —— 禁止整页由均质圆角卡片构成；同屏相同规格圆角容器 ≤2 个。来源：v1 报告页被判定为「AI 生成感」过强。
2. **每页必有可见的退出路径** —— 底部动作区不得只提供「继续深入」类操作。来源：v2 报告页两个按钮均为练习入口，无退出。
3. **界面不解释自己（UI 文案规范）** —— 禁止界面替 AI 说话、禁完整句 UI 文案、禁产品宣言、禁解释显而易见的东西。来源：v2 仍存在「你做到了」「换个说法会更自然」「前两天空着」等 AI 旁白式文案。
4. **内容直接贴背景 + 单焦点** —— 正文不套容器，封面是唯一圆角元素；每屏只一个视觉焦点。来源：v2 仍用边框框住内容且把版面填满。
5. **语音优先、文字兜底** —— 复述页以通话形态为视觉重心。来源：交互形态澄清为双向语音对话。
6. **显性纠错与对话分离** —— 对话中只做隐性重铸，文字纠错集中在报告页。来源：语音形态下语法解释听过即忘。
7. **正向表述贯穿数据呈现** —— 空缺日中性灰、不评论缺勤、补签 CTA 指向学习动作。
8. **社区不做量化比较** —— 无点赞数、无学习时长、无排行；视觉重心为推荐语而非推荐人。

### 原型阶段需解决的遗留项

示意图阶段无法处理，需在原型或开发阶段落实：

1. **封面图**：当前示意图用渐变色块占位，是最后一处明显的 demo 味来源。原型需接真实缩略图
2. **示例数据的真实性**：避免「12 天 / 28 次 / 64 条」这类过于规整的数值，改用不规整值
3. **深色主题的视觉打磨**：色值已定，但浅色为主要目标，深色的实际观感需在原型阶段验证

### Visual Spec

视觉规范详见：`design/CANVAS/visual-spec.html`（可视化版），规范正文已量化写入 §4.9。

核心决策：
- **基础色**：白 `#FFFFFF` / 夜间 `#16181C`，大面积留白，占屏 70% 以上。**浅色为主要目标，深色为第二目标**
- **高亮层**：低饱和马卡龙五色（薄荷绿主色 `#2E7D5B` / 雾霾蓝 / 丁香紫 / 奶油杏 / 浅珊瑚），仅用于小面积功能位，参考 Notion 高亮体系
- **字号**：正文基准 16px / 行高 1.7，9 级阶梯，级差刻意做大以支撑「去卡片化」的层级建立；可调三档
- **间距**：4px 基准栅格，大区块间距 32px（本规范最关键数值）
- **圆角**：卡片与按钮 10px、标签 6px
- **阴影**：除浮层与麦克风按钮外全不使用 —— 去「AI 生成感」的关键手段
- **动效**：克制。唯一常驻动效是 AI 语音声波；禁止庆祝动画、数字滚动、依次淡入、shimmer
- **深色模式**：首期同时交付，每个色值均有双主题取值
